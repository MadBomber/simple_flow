Example 8: Thread Fallback Ignores max_concurrent:
------------------------------------------------------------

When concurrency: :threads is active, max_concurrent: is
silently ignored — no error raised, all steps complete.

All steps completed? ✓ Yes
Context: {a: :done, b: :done, c: :done}

Key Takeaways:
  • concurrency: :auto (default) - auto-detects best option
  • concurrency: :threads - always uses Ruby threads
  • concurrency: :async - requires async gem, uses fibers
  • Different pipelines can use different concurrency models
  • max_concurrent: N - caps simultaneous fibers (async only)
  • max_concurrent: is silently ignored for the thread fallback
  • Use max_concurrent: to protect rate-limited APIs and
    fixed-size connection pools from thundering-herd failures
